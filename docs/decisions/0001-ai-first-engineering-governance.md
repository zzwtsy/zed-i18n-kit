# ADR 0001：采用轻量、仓库内生的 AI 开发治理

Status: accepted

## 问题

本项目计划主要由 AI 完成调查、设计、实现和验证。对话上下文不稳定，不同 Agent 对范围、验证和长期约束的理解也可能不同。如果关键决策和完成标准只存在于提示词或会话中，项目会出现重复调查、范围漂移、无法复现的验证和相互冲突的实现。

同时，项目仍处于早期骨架阶段。直接引入大型规格平台、复杂 GitHub 自动化或大量角色化 Agent，会让治理成本超过当前代码规模。

## 决定

项目采用轻量、仓库内生的治理体系：

- 根 `AGENTS.md` 保存高信号、跨任务有效的 Agent 契约；
- `docs/work/` 保存非平凡任务的范围、验收和证据，默认只有一个进行中的代码实施工作项；
- `docs/decisions/` 保存架构、持久格式、兼容性和工程流程决定；
- `docs/ai-workflow.md` 定义调查、规格、实现、验证、复核和终止生命周期；
- `scripts/check.py` 是本地与 CI 共用的基础质量门禁；
- 领域约束尽可能通过测试、schema 和 check 模式机械执行；
- 高风险修改使用新的只读上下文独立复核，人类保留范围扩张、不可逆操作和发布决定。

项目不要求所有任务使用完整 spec/plan/tasks 文档集。一个工作项文件承载早期项目所需的最小规格；真实复杂度增长后再拆分。

## 备选方案

**只使用对话提示。** 初始成本最低，但无法跨会话提供稳定权威，也不能由 CI 检查，拒绝采用。

**直接采用完整 GitHub Spec Kit。** 它提供成熟的 constitution、spec、plan、tasks 和 converge 流程，但当前仓库规模小、首个产品切片尚未实现，完整资产链会产生不必要维护成本。保留未来按需引入的可能。

**复制 DeepSeek Harness 的 Agent Notes 与门禁体系。** 该体系适合大型多包项目，但其双语记录、状态树和大量专用 gate 超过当前需求。本项目只采用决策生命周期、机器检查和高信号规则原则。

**每个 AI 工具维护独立指令。** 容易产生规则漂移。根 `AGENTS.md` 作为唯一项目契约；其他工具需要入口文件时只引用它，不复制规则正文。

## 后果

工作范围、长期决策和验证证据可以跨 Agent 会话复用，CI 与本地开发共享同一个基础入口。新增治理资产数量保持有限，并可以随 parser、rule pack、Overlay 和 runtime 风险逐步扩展。

代价是非平凡任务需要维护工作项，长期决定需要 ADR；这些文档也可能过时。因此当前事实必须只有一个权威位置，并通过链接、review 和机器门禁减少漂移。

## 验证

- 新 Agent 只阅读仓库资产即可说明项目边界、当前任务和验证命令；
- 本地与 CI 均通过 `scripts/check.py` 执行相同基础门禁；
- 非平凡改动能够从工作项追溯到验收证据；
- 规则、schema 和生成器约束逐步从文字迁移到可失败的测试或检查。

## 重新评估条件

- 同时活跃的独立实施切片长期超过一个；
- 单个工作项无法清晰承载产品规格、计划和任务依赖；
- 外部贡献者需要更完整的 Issue/PR 自动化；
- 重复流程已经稳定到值得固化为项目 skill；
- 现有治理文档维护成本明显高于其避免的返工。
