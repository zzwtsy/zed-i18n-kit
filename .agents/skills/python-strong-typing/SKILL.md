# 现代 Python 强类型

## 目标

让类型表达真实语义、数据边界和 API 约束，使错误尽量在静态分析阶段暴露，同时保持 Python 代码自然、可读并兼容项目支持的最低版本。

Python 类型注解不会自动执行运行时验证。内部代码依赖精确静态类型，外部不可信数据必须经过真实解析和校验后才能成为可信领域对象。

以 Python typing specification 为基线。遇到多个合法写法或检查器差异时，遵循仓库既有约定和已配置检查器，但不要通过扩大 `Any`、滥用 `cast` 或关闭诊断换取通过。

当任务涉及新 typing 特性、版本差异或检查器行为且仓库无法给出答案时，再读取 `references/official-sources.md` 并查阅官方资料；普通任务不必加载该文件。

## 边界与配合关系

本 Skill 只负责 Python 静态类型设计与类型安全：

- 不安装、替换或配置包管理器、格式化器、代码检查器、类型检查器或测试框架。
- 不负责一般代码风格、异常体系、资源生命周期、并发设计、性能或目录结构；这些由 `python-best-practices` 负责。
- 不修改项目最低 Python 版本，只为使用更新的 typing 语法。
- 除非任务明确要求，不改变公共 API 或运行时行为来迁就类型系统。
- 可以与 `python-best-practices` 同时使用，但不要把两份 Skill 合并成一个宽泛规则集。

## 开始前

1. 从 `pyproject.toml`、CI、容器、运行时配置和现有源码确定最低 Python 版本。
2. 检查现有公共 API、类型别名、类型检查配置、兼容层和导出方式；只读取，不擅自修改工具配置。
3. 标出类型信息会跨越的边界：JSON、环境变量、命令行、HTTP、数据库、消息、动态导入、反射和无类型第三方库。
4. 先定义外部数据如何转换为可信内部类型，再设计业务函数和返回类型。
5. 明确任务是修复局部类型错误、设计公共 API，还是建立一组可复用领域类型；避免无关的大规模注解迁移。

## 版本与现代语法

只使用项目最低 Python 版本支持的语法和标准库类型：

- Python 3.9+ 使用 `list[T]`、`dict[K, V]`、`tuple[...]`、`set[T]` 和 `type[T]`，不新增 `typing.List`、`typing.Dict`、`typing.Tuple`、`typing.Set` 或 `typing.Type`。
- Python 3.10+ 使用 `X | Y` 和 `X | None`，不新增 `Union` 或 `Optional`；可以使用 `ParamSpec`、`Concatenate` 和 `TypeGuard`。
- Python 3.11+ 在语义适合时使用 `Self`、`Never`、`assert_never`、`Required`、`NotRequired` 和 `Unpack[TypedDict]`。
- Python 3.12+ 优先使用 PEP 695 类型参数和类型别名语法：`class Box[T]`、`def first[T](...)`、`type Alias = ...`；有意覆盖父类成员时使用 `@override`。
- Python 3.13+ 在语义正确时使用 `TypeIs` 和 `ReadOnly`，不要机械替换现有可靠写法。
- Python 3.14+ 不新增 `from __future__ import annotations`。需要在运行时读取注解时使用受支持的官方接口，不直接依赖 `__annotations__` 的具体存储形式。
- 标准库已提供所需类型时优先从标准库导入。只有项目支持旧版本且已有明确兼容策略时使用 `typing_extensions`。
- 从 `collections.abc` 导入适合运行时与注解共同使用的抽象容器和 `Callable`，遵循项目最低版本和现有约定。
- 不新增 `AnyStr`、`Text`、旧式 `# type:` 注释、关键字形式 `TypedDict` 或其他已被现代语法取代的写法。

## 注解覆盖与精度

- 为新增或修改的函数和方法完整标注参数与返回值，包括 `-> None`、`*args`、`**kwargs`、生成器和异步生成器。
- 公共 API、协议、回调、领域对象和跨模块返回值必须具有稳定、精确的类型。
- 不使用裸容器、裸泛型或未参数化协议，例如 `list`、`dict`、`Callable`、`Iterable`。
- 局部变量优先依赖推断；只有空容器、递归结构、联合收窄或公共语义不清时添加显式局部注解。
- `async def` 的返回注解表示 `await` 后的结果，不标注为 `Coroutine`，除非函数本身返回协程对象而不是通过 `async def` 定义。
- 根据实际生成器能力选择 `Iterator[T]`、`Generator[Y, S, R]`、`AsyncIterator[T]` 或 `AsyncGenerator[Y, S]`。
- 类型不能比运行时事实更窄。可选值、失败分支、空集合和延迟初始化必须在类型中真实体现。

## API 类型设计

- 输入参数只要求调用方提供函数真正需要的最小能力。只读输入优先使用 `Iterable`、`Collection`、`Sequence`、`Mapping` 或小型 `Protocol`；需要修改时才使用可变抽象或具体容器。
- 具体实现的返回值优先暴露明确、稳定的具体类型，例如 `list[T]` 或 `dict[K, V]`，不要无理由返回宽泛可变接口。
- 返回形状保持单一、可预测。只有多个分支属于真实领域模型且调用方能可靠收窄时使用联合返回类型。
- 参数与返回值存在关系时用类型参数表达，不要把相关类型分别写成互不关联的联合或 `Any`。
- 类型别名用于命名复杂结构和提升可读性；需要区分相同底层表示的领域概念时使用 `NewType`、枚举或领域类。
- 不用 `Any` 表达“我还没有决定 API”；先确定最小稳定契约。

## `Any`、`object` 与逃生口

- 新代码不得产生隐式 `Any`。公共 API 中默认禁止显式 `Any`。
- 参数可接收任意 Python 对象但不能执行任意操作时使用 `object`，不要使用 `Any`。
- 无法避免的动态类型限制在最小边界内，并立即通过运行时验证、收窄或适配层转换为精确类型。
- 不把 `json.loads()`、数据库原始行、环境变量、网络响应、插件结果或未知第三方返回值直接 `cast` 为可信领域类型。
- `cast()` 不执行运行时检查。仅当事实已由程序不变量保证、但类型系统无法表达时使用，并把范围限制在单个表达式附近。
- 优先修正类型模型，不用 `cast` 代替正常的 `isinstance`、`is None`、成员判断、模式匹配或解析函数。
- 类型忽略只能用于已确认无法正确建模的外部限制，必须针对具体诊断、限制在最小行并说明原因。禁止文件级或宽泛抑制。
- 不使用 `Callable[..., Any]`、`dict[str, Any]` 或 `object` 作为默认回退来让诊断消失。

## 外部边界与运行时验证

以下来源默认不可信：

- JSON、TOML、YAML、CSV 和任意反序列化结果。
- 环境变量、命令行参数、表单、HTTP 请求和响应。
- 数据库原始行、缓存载荷、消息队列和事件总线消息。
- 动态导入、插件钩子、反射结果和无类型第三方库。

在边界执行真实解析与验证：

- 先验证容器类型、必需字段、字段类型、范围和跨字段不变量。
- 验证成功后构造 `dataclass`、领域类、枚举、`NewType` 值或精确 `TypedDict`。
- 失败时返回明确的解析错误或抛出领域异常，不让部分可信对象进入核心逻辑。
- `TypedDict`、`NewType`、`Final`、`ReadOnly` 和大多数 typing 构造只提供静态语义，不得依赖它们阻止运行时错误。

## 领域类型工具选择

- `NewType`：底层表示相同但不应混用的 ID、单位值或句柄。
- `Literal`：轻量、封闭且无需运行时行为的固定值集合。
- 枚举：需要运行时身份、遍历、方法或稳定序列化语义的状态集合。
- `TypedDict`：必须保持字典形状的互操作边界或协议载荷。
- `dataclass` 或领域类：具有行为、不变量、默认值、生命周期或稳定身份的内部记录。
- 小型 `Protocol`：调用方只依赖一组结构化能力，不要求实现类显式继承。
- ABC 或名义继承：确实需要运行时继承、共享实现、显式注册或受控扩展点。
- `Annotated`：已有运行时框架消费元数据时使用，不把它当作普通注释。
- `dataclass_transform`：仅用于实现真正的数据类框架或装饰器，不用于普通业务模型。

## 泛型与类型参数

- 只有在需要保持输入输出关系、元素类型、键值关系或子类类型时引入泛型。
- 一个实现只处理具体类型时保持具体，不为形式上的“可复用”增加无意义类型参数。
- 子类型上界使用 bound；有限的精确替代集合使用 constraints。不要把二者混用来描述含糊关系。
- 只读生产者、可变消费者和双向容器的型变必须符合真实读写能力；不要为通过检查器手工声明不安全型变。
- 返回当前实例或对应子类实例的方法、替代构造器和上下文管理器在语义正确时使用 `Self`。
- 不把互不相关的输入和输出绑定到同一个类型参数，也不为多个独立关系复用同一个参数。

## 回调、装饰器与重载

- 简单回调使用精确的 `Callable[[...], R]`。
- 包含关键字专用参数、重载、属性或复杂调用约束时，定义带 `__call__` 的小型 `Protocol`。
- 装饰器保留原函数调用签名时使用 `ParamSpec`，保留返回类型时同时使用返回类型参数。
- 装饰器注入或移除位置参数时在 `ParamSpec` 基础上使用 `Concatenate`，不要退化为 `Callable[..., Any]`。
- 固定 `**kwargs` 键集合且版本支持时使用 `Unpack[TypedDict]` 表达关键字名称、必需性和值类型。
- 优先用泛型表达返回关系。只有返回类型确实依赖字面量参数、参数组合或既有重载协议时使用 `@overload`。
- 每组重载必须有一个与全部重载兼容的运行时实现；重载顺序覆盖更具体分支，且实现行为与声明一致。
- 不用大量重载掩盖设计含糊、参数爆炸或彼此无关的多个 API。

## 收窄与穷尽性

- 优先依赖普通控制流收窄：`isinstance`、`issubclass`、`is None`、成员判断、枚举比较、字面量标签和模式匹配。
- 可复用谓词的目标类型是输入类型的兼容子类型时，Python 3.13+ 优先使用 `TypeIs`。
- 只有不满足 `TypeIs` 子类型要求，例如需要处理不变容器时，才使用 `TypeGuard`。
- 收窄函数必须真实、完整地实现其声明；错误的 `TypeIs` 或 `TypeGuard` 会破坏整个类型模型。
- 对封闭联合使用可辨识字段、`Literal` 或枚举作为标签，并在分支末尾使用 `assert_never` 检查穷尽性。
- 永不正常返回的函数在版本支持时优先标注 `Never`；兼容旧版本或遵循既有代码时可保留 `NoReturn`，不要无理由混用。
- 不通过断言掩盖可达分支。断言只表达程序已建立且失败即为内部缺陷的不变量。

## `Protocol`、继承与覆盖

- `Protocol` 面向调用方需求设计，只包含真正使用的成员；不要复制实现类的完整接口。
- 不为每个类创建同名协议，也不要求实现类显式继承结构化协议。
- 只有确实需要 `isinstance` 或 `issubclass` 时使用 `@runtime_checkable`；它不能验证完整成员签名。
- 所有有意覆盖父类成员的方法在版本支持时使用 `@override`。
- 覆盖方法不能缩窄父类接受的参数，也不能返回不兼容类型。
- 使用 `ClassVar` 区分类状态和实例状态，使用 `Final` 表达名称不可重新绑定，使用 `@final` 表达禁止继承或覆盖的设计决定。

## 运行时注解与反射

- 类型注解不是运行时验证器，也不保证对象满足注解。
- 需要解析注解时使用 `typing.get_type_hints()` 或当前 Python 版本提供的官方注解接口，不直接依赖内部缓存或私有 typing 类型。
- Python 3.14+ 的注解采用延迟求值语义；不要假设 `__annotations__` 中始终存放字符串或已求值对象。
- 谨慎使用 `TYPE_CHECKING`。不要隐藏运行时框架、序列化、依赖注入、插件发现或反射实际需要的名称。
- 不在运行时使用 `typing` 私有类判断联合、泛型或别名；使用 `get_origin()`、`get_args()` 等公开接口。

## 完成标准

完成修改前确认：

- 改动范围内的函数、方法、回调和公共对象签名完整且精确。
- 没有新增隐式 `Any`、裸泛型或无理由的显式 `Any`。
- 不可信数据在边界经过运行时验证，未被直接断言或强转为可信领域类型。
- 泛型、协议、重载和联合表达真实关系，而不是增加形式复杂度。
- `cast` 和类型忽略已移除，或限制在无法避免的最小边界并有明确理由。
- 封闭联合能够穷尽检查，继承覆盖已按版本标记 `@override`。
- 注解和运行时行为一致，且兼容项目最低 Python 版本。
- 未擅自修改类型检查器或工具链配置。
- 已运行仓库现有类型检查和相关测试；无法执行的项目必须如实说明。

## 输出要求

- 保持改动聚焦，不顺带重构与类型安全无关的代码。
- 简要说明重要的类型模型、外部边界、版本选择和仍存在的逃生口。
- 报告执行过的验证命令及结果，不声称未执行的检查已通过。
